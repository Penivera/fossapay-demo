One client, two transports

FossaPay is production-only: there is no sandbox, and a live key moves real money. So every demo talks to a shared client that can run against an in-memory ledger or the real API, with no change to your product code.

your app code | FossaPayClient |-- mock --> in-memory ledger | offline, free, signs webhooks '-- live --> api-production.fossapay.com

Idempotency everywhere

Keys derive from your own business IDs, so a retry after a crash can never pay twice.

Signed webhooks, done right

Both documented signature schemes, timing-safe comparison, de-duplication, and failure to a closed door when no secret is set.

Money without floats

Whole-naira requests, kobo-integer maths, and remainder-safe splitting.

Quick start

Node.js 20+ is all you need.

git clone https://github.com/Penivera/fossapay-demo.git
cd fossapay-demo
npm install
npm run build --workspace=packages/fossapay-client

npm run dev:safedeal     # http://localhost:3001
npm run dev:squadpay     # http://localhost:3002
npm run dev:ajosphere    # http://localhost:3003
npm run dev:offramp      # http://localhost:3000
  1. Run in sandbox. No configuration. Click through a whole journey, including simulated payments and webhooks.
  2. Read the code. Each demo's store file is the integration, in one place.
  3. Go live carefully. Set FOSSAPAY_MODE=live, a key and a webhook secret. Forms go blank and simulators disappear. Read the checklist first.
